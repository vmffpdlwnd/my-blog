CardClickerRPG

AWS Lambda와 DynamoDB로 서버 없이 백엔드를 구성한 콘솔 카드 RPG

GitHub → Download →

개요

클릭으로 재화를 모아 카드를 얻고, 덱을 강화해 전투력 랭킹을 겨루는 C# 콘솔 RPG입니다. 서버를 직접 띄우지 않고 AWS Lambda와 DynamoDB로 서버리스 백엔드를 구성했습니다.

문제 상황

처음에는 클라이언트가 AWS SDK로 DynamoDB에 바로 접근했습니다. 이 방식은 클라이언트에 AWS 자격 증명이 들어가야 해서, 배포하는 순간 키가 노출됩니다.

내 역할

혼자 진행했습니다. 게임 로직, 클라이언트, 백엔드 구성을 모두 맡았습니다.

  • 카드 등급(common~legendary)과 능력(자동 클릭, 클릭 배율, 가루 보너스, 강화 할인, 행운), 덱 자동 편성, 강화와 분해를 만들었습니다.
  • 데이터 통신을 기능별 Lambda Function URL(플레이어 조회·생성·수정, 카드 조회·추가·삭제·강화 등 10개)로 나눴습니다.
  • PlayFab으로 로그인과 덱 전투력 리더보드를 붙였습니다.

  • .NET을 설치하지 않아도 실행되는 단일 exe로 GitHub Releases에 배포했습니다.

트러블슈팅

클라이언트에 들어간 AWS 키를 없애기까지

DynamoDB 직접 접근 방식은 키 노출 문제 때문에 바꿔야 했습니다. 먼저 PlayFab CloudScript로 옮겨 봤다가 걷어 냈고, 이후 Lambda로 통신 계층(LambdaService)을 분리하고, 마지막에 기능별 Lambda Function URL로 전환하면서 DynamoDBService를 제거했습니다. 클라이언트는 이제 URL만 알고, DynamoDB 접근 권한은 Lambda만 가집니다.

설정 파일이 통째로 무시되던 문제

AWS 자격 증명 폴더(.aws/)를 제외하려던 .gitignore 규칙이 Config 폴더까지 제외하고 있었습니다. 규칙을 고쳐 비밀 값만 빠지고 설정 코드는 올라가게 했습니다.
